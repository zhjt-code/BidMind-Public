# 测试数据政策

本仓库面向公开协作。测试价值不能以泄露客户材料、个人信息或无权再分发的内容为代价。

## 允许提交

1. 完全合成的数据；
2. 已公开发布、确认允许再分发，并完成身份信息清理的招标规则片段；
3. 不可逆的聚合指标和不含原文的匿名契约样本。

## 禁止提交

- 客户投标文件、证件、合同、印章、签名、银行或税务材料；
- 姓名、手机、邮箱、详细地址、身份证号、统一社会信用代码等可识别信息；
- 具体公司、机构或银行名称；需要表达主体关系时统一使用 `<PERSON_A>`、`<ORG_A>`、`<PHONE_A>` 等匿名占位符；
- 私有专家意见、盲评记录、原始文件哈希或私有存储索引；
- 原始上传文件名、原始本机路径及可反向关联源文件的元数据；
- API 密钥、SSH 密钥、生产地址、内部域名和本机绝对路径。

## 当前公开数据分类

- `tests/regression/`：场景矩阵生成的合成回归数据，以及无原文匿名契约样本；
- `backend/eval/golden_datasets/`：虚构主体和占位联系方式组成的合成评测样本；
- `backend/tests/fixtures/scoring/`、`backend/tests/fixtures/relevance/`：经身份信息清理的评分与规则片段，只用于解析和判定回归；
- 原始 PDF、客户样本和私有标注不属于公开仓库。

## 新增数据检查

新增或更新测试数据时，需要在 PR 中说明来源类别和清理方式，并运行：

```bash
python scripts/check_public_data.py
```

自动检查只能发现常见模式，不能替代人工逐项确认来源、授权和可识别信息。

必须测试身份证号、信用代码或电话号码等格式算法时，使用测试辅助函数从分段的虚构片段动态构造，不在源码或夹具中保存完整号码。
